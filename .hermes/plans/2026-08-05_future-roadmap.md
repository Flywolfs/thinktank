# 情报系统 — 未来开发 Roadmap

> 核心架构原则（2026-08-05 用户确认）：
> **Plan 决策层**：要聪明、准确、专业 → 两条路线并行对比
> **Execute 执行层**：可复现、可重复调用、可追踪的工具（爬虫/抽取/打分/图谱）
> Plan 的"智能"可以外包，Plan 的"执行与沉淀"留在系统

## Phase 0: Plan 决策层升级（当前优先级最高）

### P0.1 路线 A — plan_node 多轮推理版
**目标**：把单次 LLM 调用升级为多步推理，逼近 Hermes 的 plan 质量，不改架构。

```
plan_node v2 内部流程（同一节点，多步推理）:
  1. 实体类型分析   → LLM 判断: 企业家/公众人物/公司/事件/其他
  2. 候选维度生成   → LLM 基于实体类型+方法论映射表生成候选维度
  3. 维度筛选排序   → 按 hints 优先级 + 基线档案永远第一
  4. 自检合理性     → LLM 检查: 维度是否覆盖不同层面？是否引用方法论？是否重叠？
  5. 修正输出       → 自检发现问题则修正，最终输出 JSON
```

- 关键：多步推理之间保留中间状态（可追踪），不只是"一次调用塞更多 prompt"
- 验证：对比 v1 单次调用 vs v2 多轮，用蒋方舟/雷军/韩红 3 案例

### P0.2 路线 B — Docker 部署专用 Hermes Agent
**目标**：部署一个精简的 Hermes Agent，专职做两件事：
1. 情报 plan 决策（接收实体+hints → 返回维度模板 JSON）
2. 额外爬虫代码编写（为 Phase C 动态工具创建做准备）

**部署步骤**：
- [ ] 查 Hermes Docker 部署官方文档（https://hermes-agent.nousresearch.com/docs）
- [ ] Docker 部署 Hermes Agent（独立 profile，如 `intel-planner`）
- [ ] 加载精简 skills：情报方法论 skill（INVESTIGATION_METHODOLOGY.md 打包）
- [ ] 加载核心 MCP：web_search/web_extract 等必要工具
- [ ] **禁用无关工具**（省 token）：关闭爬虫/文件/代码等本次不需要的
- [ ] 定义接口：接收 `{entity, hints, goal}` → 返回维度模板 JSON（与系统格式一致）
- [ ] 验证：用同一实体跑路线 B，对比路线 A 的 plan 质量

### P0.3 双路线对比评估
- [ ] 同一实体（蒋方舟/雷军/韩红）分别用 A/B 生成 plan
- [ ] 对比维度质量：覆盖度/方法论引用/搜索角度具体性/hints 响应
- [ ] 决策：选优 / 融合（A 快速兜底 + B 深度决策）/ 双跑

## Phase 1: Execute 执行层工具化

### P1.1 Tool Registry（工具注册表）
- [ ] 现有 7 个 Provider 包装成带元信息的工具（name/description/参数/成本）
- [ ] 工具清单作为上下文交给 LLM，function calling 动态选择
- [ ] 移除硬编码工具选择规则（如"搜外国人跳过中国企业源"已弃用）

### P1.2 执行步骤工具化
- [ ] 每个步骤可独立调用（不只是串联在调查图里）：
  - [ ] 爬虫工具：7 个数据源可单独调用（已有，补元信息）
  - [ ] 实体抽取工具：单独可调用，输入文本→输出实体
  - [ ] 相关性打分工具：单独可调用，输入结果集→输出打分
  - [ ] 信息整合推理工具：单独可调用
  - [ ] 知识图谱工具：单独可调用
- [ ] 每个工具调用留痕（日志已有，补到工具级审计）

### P1.3 工具级审计
- [ ] 每个工具调用的 输入/输出/耗时/参数 全记录
- [ ] 支持"这次调查调用了哪些工具、每个工具返回什么"的完整回放

## Phase 2: 核心缺失功能

### P2.1 Phase C — 动态工具创建（复用 P0.2 的 Hermes Agent）
- [ ] 调查中 agent 提出"需要知乎/微博/某网站"但 crawler 集合没有
- [ ] 调用 Docker Hermes Agent（写代码能力）→ 生成爬虫代码
- [ ] 代码保存到 `tools/dynamic/` → importlib 加载 → 注册进 Tool Registry
- [ ] 下一轮调查即可用新工具
- [ ] 安全：动态代码沙箱/审批（写代码是可执行操作，需人确认）

### P2.2 线索并行（多实体同时深挖）
- [ ] LangGraph Send API：追出多条线索时，每条线索独立子调查并行
- [ ] 解决速度瓶颈（现在 10 条线索串行 = 20-30 分钟）
- [ ] 并行结果合并去重

### P2.3 用户中途调整调查方向
- [ ] analyze_leads 节点加 interrupt 暂停点
- [ ] 用户可输入"别追争议了，专注资金链" → 剩余维度重排
- [ ] 前端加"调整方向"输入框
